# Docspace · Main Management

Version **0.0.2**

UI ใช้ภาษาอังกฤษทั้งหมด ทั้งเมนู ปุ่ม tooltip ข้อความสถานะ และข้อความแจ้งข้อผิดพลาด ชื่อไฟล์และเนื้อหาเอกสารแสดงตามต้นฉบับ

ทุกเมนูใช้ตัวเลือกปลายทางชุดเดียวกัน: ช่องพาธพร้อมไอคอนโฟลเดอร์และปุ่ม **Change folder** ขนาด/สี/ตัวอักษรเดียวกัน พาธยาวย่อด้วยจุดไข่ปลาและชี้เมาส์เพื่อดูพาธเต็ม ช่อง **Save PNG to** ของ Heatmap ยังแก้ชื่อไฟล์ได้ ตัวเลือกนี้สร้างจาก `ui_components.py` และใช้สไตล์ร่วมใน `ui/destination.css`

รวมโปรแกรมจาก Doc_management และ Heat-Map เป็นแอป Desktop หน้าต่างเดียว
branch พัฒนาเพิ่มเมนู **Organize PDF** สำหรับรวมและแยกหน้าเอกสาร โดยยังไม่ได้เปลี่ยนเลขเวอร์ชัน
ใช้เมนูด้านซ้ายสลับเครื่องมือ โดยรายการ PDF และค่าที่กรอกใน Heatmap ยังคงอยู่เมื่อสลับหน้า
เปิดหน้า PDF ก่อน และโหลดการคำนวณ Heatmap เมื่อเลือกเมนู Heatmap ครั้งแรก เพื่อลดเวลารอเข้าโปรแกรม

- **PDF to Image**: เพิ่ม PDF หลายไฟล์ด้วยปุ่มหรือลากวาง ดูตัวอย่างแต่ละหน้า ซูม เลือกหน้าส่งออกเป็น JPG, PNG หรือ WebP และยกเลิกระหว่างทำงาน
- **จัดการหน้า PDF**: grid/list ภาพย่อรายหน้า ลากเรียงข้ามไฟล์ เลือกหลายหน้า หมุน ลบ ย้อนกลับ และรวม/แยก PDF ใหม่
- **Heatmap**: กำหนดอุณหภูมิและ X/Y ของ 6 จุด ลากตำแหน่งบนแผนผัง และประมาณสีเต็มพื้นที่ด้วย IDW พร้อมดูตัวอย่างและส่งออก PNG
- **Compress PDF**: ลดขนาด PDF หลายไฟล์ด้วย Lossless, Balanced หรือ Smallest แสดงขนาดก่อน/หลังและพื้นที่ที่ประหยัดได้ บันทึกเป็นสำเนาใหม่
- **Searchable PDF · OCR**: เพิ่มชั้นข้อความที่ค้นหา/คัดลอกได้ให้ PDF สแกน รองรับหลายภาษา ทำงานด้วย CPU ไม่ต้องมี GPU
- ทำงานภายในเครื่อง ไม่ต้องใช้เว็บเซิร์ฟเวอร์
- คัดลอกซอร์สที่จำเป็นมาไว้ในโฟลเดอร์นี้แล้ว สามารถใช้งานโดยไม่อ้างอิงสองโฟลเดอร์ต้นฉบับ
- ไฟล์งานและผลลัพธ์เดิมในสองโฟลเดอร์ต้นฉบับยังอยู่ที่เดิม เลือกเปิดหรือเลือกปลายทางจากหน้าจอได้

## เปิดใช้งานบน Windows

ดับเบิลคลิก `start_ui.vbs` หรือ `start_ui.bat`
ตัวเปิดโปรแกรมใช้ `.venv` ในโฟลเดอร์นี้ มีหน้าจอโหลดและบันทึกข้อผิดพลาดที่ `.webview/startup.log`

ติดตั้งใหม่เมื่อย้ายเครื่อง (Python 3.10+ และ Microsoft Edge WebView2 Runtime):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

เปิดผ่านคำสั่ง:

```powershell
.\.venv\Scripts\python.exe main_app.py
```

## ฟังก์ชัน PDF ในเวอร์ชัน 0.0.2

ทุกเครื่องมือ PDF สร้างโฟลเดอร์ส่งออกโดยขึ้นต้นด้วยชื่อไฟล์ต้นฉบับ เช่น `Invoice.pdf`:

| เมนู/งาน | โฟลเดอร์ตัวอย่าง |
|---|---|
| PDF to Image | `Invoice_images` |
| Compress PDF | `Invoice_compressed` |
| Searchable PDF · OCR | `Invoice_searchable` |
| Organize PDF · แยกเป็นไฟล์ต่อหน้า | `Invoice_split` |
| Organize PDF · เลือกหน้าต่อไฟล์ต้นฉบับ | `Invoice_extracted` |
| Organize PDF · รวมไฟล์เดียว | `Invoice_merged` |

เมื่อรวมหลายไฟล์ ใช้ชื่อไฟล์แรกตามลำดับที่จัดหน้าและจำนวนไฟล์ต้นฉบับอื่น เช่น `Invoice_and_2_more_merged` สำหรับ 3 ไฟล์ ส่วน extract/split แยกโฟลเดอร์ให้ต้นฉบับแต่ละไฟล์ ชื่อซ้ำเติม `_2`, `_3`, … โดยจองโฟลเดอร์ด้วย mkdir แบบ atomic จึงไม่ทับไฟล์หรือการส่งออกพร้อมกัน รองรับชื่อไทย/เว้นวรรค ชื่อยาวเกิน 80 UTF-16 units ตัดเฉพาะส่วนชื่อโฟลเดอร์และยังแยกชื่อซ้ำได้ ใช้กฎร่วมใน `export_folders.py` มีผลกับการส่งออกครั้งถัดไป Heatmap ใช้ชื่อไฟล์ PNG ที่กำหนดใน **Save PNG to**

- ลากไฟล์ PDF จาก File Explorer ลงบนหน้า PDF หรือแถบด้านซ้ายได้ โดยไม่มีข้อความหรือกล่องกำกับการลากวาง รองรับหลายไฟล์และไม่เพิ่มไฟล์เดิมซ้ำ ไฟล์ที่อ่านไม่ได้จะแสดงข้อผิดพลาดในรายการ
- เลือก PDF ในรายการ แล้วเลือก **Export pages** จาก dropdown: **All pages** (ทุกหน้า), **Current page** (หน้าที่แสดงในตัวอย่าง), **Custom pages** (ระบุหน้าเอง), **Even pages** (หน้าคู่) หรือ **Odd pages** (หน้าคี่) ใช้เลขหน้า PDF เริ่มจาก 1
- ช่องกรอกช่วงหน้าจะแสดงเฉพาะ **Custom pages** เช่น `1-3, 5` หรือ `1–3, 5` แต่ละ PDF มีตัวเลือกแยกกัน ค่าจะอยู่ระหว่างสลับไฟล์หรือเครื่องมือภายในรอบการเปิดแอป หากเลือกหน้าคู่ใน PDF ที่มีเพียงหน้าเดียว โปรแกรมจะแจ้งว่าไม่มีหน้าคู่
- ช่วงหน้าต้องอยู่ภายในเอกสาร เรียงจากน้อยไปมากภายในแต่ละช่วง โปรแกรมรวมเลขหน้าที่ซ้ำและส่งออกตามลำดับหน้า ชื่อภาพใช้เลขหน้าต้นฉบับ เช่น `page_005.jpg`
- กด **Cancel conversion** เพื่อหยุดงาน โปรแกรมตรวจคำขอยกเลิกระหว่างหน้าและหลังเรนเดอร์หน้า จึงอาจต้องรอขั้นตอนเรนเดอร์หรือบันทึกภาพปัจจุบันก่อน ภาพที่บันทึกแล้วจะเก็บไว้ PDF ที่ยังไม่เริ่มจะถูกยกเลิกด้วย
- หลังยกเลิก สามารถเปลี่ยนหน้าหรือค่าต่าง ๆ แล้วกดแปลงใหม่ได้ โปรแกรมสร้างโฟลเดอร์ใหม่เพื่อไม่เขียนทับภาพรอบก่อน
- ปุ่ม **Cancel conversion** ใช้พื้นหลังสีแดงเพื่อแยกจากปุ่มดำเนินงาน เมื่อกดแล้วเปลี่ยนเป็นสถานะ Cancelling และกดซ้ำไม่ได้
- งานแปลง PDF ทำใน process แยกจากส่วนควบคุมหน้าจอ และใช้ลำดับความสำคัญต่ำกว่างานปกติบน Windows เพื่อลดอาการหน่วงระหว่างแปลง โดยยังคงแจ้งความคืบหน้าและยกเลิกระหว่างหน้าได้

## หน้าต่างและโลโก้

- เมื่อปิดแอปตามปกติ โปรแกรมจำขนาด ตำแหน่ง และสถานะขยายเต็มจอของหน้าต่างหลักไว้ เปิดครั้งถัดไปจะคืนค่าเดิม หากตำแหน่งเดิมอยู่นอกจอจะปรับกลับเข้าสู่จอที่มีอยู่
- การปิดขณะเต็มจอเก็บขนาดหน้าต่างก่อนขยายไว้ด้วย จึงกด Restore แล้วกลับไปขนาดเดิมได้ การย่อไป taskbar จะไม่ทำให้เปิดรอบใหม่เป็นหน้าต่างที่ซ่อนอยู่
- โลโก้และไอคอนเมนูในหน้าต่างหลักใช้ SVG โลโก้หน้าจอโหลดใช้ PNG 512×512 ปรับขนาดตาม DPI และไอคอน Windows ใช้ ICO หลายขนาดตั้งแต่ 16 ถึง 256 พิกเซล

## จัดการหน้า PDF

1. เปิดเมนู **จัดการหน้า PDF** แล้วกด **เพิ่ม PDF** หรือลากไฟล์จาก File Explorer ลงหน้าจอ แต่ละหน้าจะแสดงเป็นการ์ดภาพย่อใน grid สลับเป็น list ได้จากปุ่มด้านขวาบน
2. คลิกภาพย่อหรือ checkbox เพื่อเลือกหลายหน้า ใช้ Shift + คลิกเพื่อเลือกเป็นช่วง และ **เลือกทั้งหมด** สำหรับหน้าที่แสดงอยู่ กรองตามชื่อไฟล์ได้โดยไม่เปลี่ยนลำดับส่งออก
3. ลากภาพย่อเพื่อเรียงหน้า รวมถึงข้ามเอกสาร ถ้าลากหน้าที่เลือกอยู่จะย้ายทั้งกลุ่มตามลำดับเดิม มีปุ่มย้ายก่อนหน้า/ถัดไปสำหรับใช้แทนการลาก
4. กดปุ่ม **หมุน / พลิก** บนการ์ด หรือใช้แถบเครื่องมือสำหรับหน้าที่เลือก เลือกหมุนซ้าย/ขวา 90°, หมุน 180°, พลิกซ้าย–ขวา (แนวนอน), พลิกบน–ล่าง (แนวตั้ง) หรือคืนค่าต้นฉบับได้ ผลลัพธ์ PDF ใช้มุมและการพลิกเดียวกับตัวอย่าง กด **ย้อนกลับ** หรือ Ctrl+Z เพื่อคืนการเรียง หมุน พลิก หรือลบล่าสุด เก็บประวัติได้ 25 ขั้นภายในรอบเปิดแอป การเพิ่ม/ล้างไฟล์เริ่มประวัติใหม่
5. กดแว่นขยายหรือดับเบิลคลิกภาพย่อเพื่อเปิด popup ตัวอย่าง มีปุ่ม + / −, **Fit page** และ **Fit width** ซูมด้วย Ctrl + ล้อเมาส์หรือจีบสองนิ้วเฉพาะภาพใน popup เลื่อนเพื่อดูส่วนอื่น และเปิดเมนูหมุน/พลิกได้จาก popup โดยเปิดแต่ละครั้งเริ่มจาก Fit page การซูมทั้ง WebView ถูกปิดเพื่อไม่ให้เมนูและปุ่มทั้งแอปขยายตามภาพ
6. แผงบันทึกด้านขวาเลือกส่งออก **ทุกหน้าที่จัดไว้** หรือ **เฉพาะหน้าที่เลือก** พร้อมจำนวนหน้าก่อนบันทึก จากนั้นเลือกวิธีจัดการ:
   - **รวมเป็น PDF เดียว** — รวมตามลำดับภาพย่อเป็น `merged.pdf`
   - **แยกตามไฟล์ต้นฉบับ** — สร้าง PDF หนึ่งไฟล์ต่อเอกสาร โดยใช้ลำดับหน้าที่จัดไว้ภายในแต่ละต้นฉบับ
   - **แยกทุกหน้าเป็น PDF** — สร้าง PDF หนึ่งไฟล์ต่อหน้าที่ส่งออก ชื่อไฟล์ระบุเลขหน้าต้นฉบับ
7. เลือกโฟลเดอร์ แล้วกด **บันทึก PDF** ผลลัพธ์อยู่ในโฟลเดอร์ที่ตั้งตามต้นฉบับและงาน เช่น `Invoice_merged`, `Invoice_extracted`, `Invoice_split` ชื่อซ้ำเติม `_2`, `_3` เพื่อไม่เขียนทับผลลัพธ์เดิม งาน extract/split หลายต้นฉบับแยกโฟลเดอร์ให้แต่ละไฟล์

คัดลอกหน้า PDF โดยตรง ไม่แปลงเป็นรูปภาพ จึงคงข้อความและกราฟิกเดิมไว้ งานทำใน process เบื้องหลังและกดยกเลิกได้เมื่อขั้นตอนปัจจุบันเสร็จ ในโหมดรวม/แยกตามต้นฉบับตรวจยกเลิกระหว่างเอกสารและก่อนบันทึก ส่วนแยกทุกหน้าตรวจระหว่างหน้า ไฟล์ PDF ที่บันทึกสำเร็จแล้วจะเก็บไว้

รายการหน้า ลำดับ มุมหมุน และการเลือกแยกจาก PDF to Image และยังอยู่เมื่อสลับเมนูภายในรอบที่เปิดแอป โหลดภาพย่อเฉพาะบริเวณที่เห็นและใกล้ตำแหน่งเลื่อน ทีละภาพ แคชไม่เกิน 120 ภาพ และถอดภาพที่อยู่นอกพื้นที่ออกจากการ์ดเพื่อลดหน่วยความจำ ไฟล์อ่านไม่ได้จะแจ้งเมื่อเลือกตัวกรองชื่อไฟล์นั้น ไม่มีการแก้ไขไฟล์ต้นฉบับ

เลือกหน้าจาก command line ได้ด้วย:

```powershell
.\.venv\Scripts\python.exe pdf_to_jpg.py "input\sample.pdf" --pages "1-3,5" --format png
```

## Temperature Heatmap: ตำแหน่งวัดและสีทั่วพื้นที่

1. ใน **Measurements** กรอกชื่อและอุณหภูมิของ 6 จุดได้ทันที ช่อง **X/Y** เป็นตัวเลือกเพิ่มเติม: กดลูกศร **Position** ของแต่ละแถวเพื่อเปิดหรือซ่อน ไม่ถูกบังคับเป็นกริด 2×3 อีกต่อไป รูปแบบ 2×3 ใน JSON เป็นเพียงการเก็บค่าจุด 1–6
2. เปิด **Area & point layout** เพื่อกำหนด Width/Height และหน่วย (relative, mm, cm, m) แล้วคลิกภาพย่อ **Edit point layout** เพื่อเปิด popup ขนาดใหญ่ ลากจุดหรือเลือกชื่อจุดจากรายการขวาได้ พร้อมดู X/Y ของจุดที่เลือก โฟกัสจุดแล้วกดลูกศรเพื่อเลื่อน 1% ของขนาดพื้นที่; Shift + ลูกศรเลื่อน 5% จุดเริ่มต้น (0,0) อยู่มุมซ้ายบน X ไปขวา Y ลงล่าง กด **Done** หรือ Esc เพื่อกลับ โดยการแก้ตำแหน่งมีผลทันทีและรอ Update preview
3. เลือก **Full area · IDW** เพื่อประมาณอุณหภูมิทั่วสี่เหลี่ยม รวมถึงบริเวณนอกกลุ่มจุดวัด ค่า **Power** ปรับได้ตั้งแต่ 1–5 (เริ่มต้น 2) ค่าใหญ่เพิ่มอิทธิพลของจุดใกล้มากขึ้น
4. กด **Update preview** แล้ว **Export PNG** พิกัด โมเดล และ Power ถูกบันทึกใน `heatmap_settings.json` พร้อมค่าที่กรอก และคืนค่าเมื่อเปิดแอปใหม่

ใน popup **Point layout** มี **Show grid**, **Snap to grid** และ **Grid spacing** ใช้ระยะเดียวกันทั้ง X/Y ตามหน่วยพื้นที่ เช่น 0.5 cm เริ่มต้นแสดง grid แต่ปิด Snap เพื่อคงการลากอิสระ เปิด Snap แล้วการลากจะเกาะจุดตัดใกล้สุดหรือขอบพื้นที่ ปุ่มลูกศรเลื่อนไป grid ถัดไป และ Shift + ลูกศรเลื่อน 5 ช่อง โดยไม่ให้จุดซ้อนกัน

ใช้ **− / +** หรือเลื่อนล้อเมาส์เหนือพื้นที่เพื่อซูม 50–800% เฉพาะแผนผัง ปุ่ม **Fit** คืนมุมมองให้เห็นทั้งหมด ลากพื้นหลังเพื่อเลื่อนพื้นที่เมื่อซูมเข้า และเลือกจุดจากรายการด้านขวาเพื่อเลื่อนมาที่จุดนั้น จุดวัดมีขนาดคงที่ 18 px พร้อมพื้นที่รับการลากที่กว้างกว่า จึงไม่บัง grid เมื่อขยาย การซูมและเลื่อนมุมมองไม่เปลี่ยนพิกัดจริง

การเปิด Snap หรือเปลี่ยนระยะไม่ขยับจุดเดิมอัตโนมัติ และยังพิมพ์ X/Y ละเอียดได้ตามเดิม การซ่อนเส้น grid ไม่ปิด Snap หาก grid ละเอียดจนวาดเส้นไม่เหมาะกับขนาดแผนผัง โปรแกรมจะซ่อนเส้นพร้อมข้อความแจ้ง แต่ยัง Snap ด้วยระยะที่ระบุ ค่า grid/Snap จะถูกจำเมื่อ Update preview หรือ Export PNG และเป็นเพียงตัวช่วยวางจุด ไม่ใช่ Grid rows/columns ของภาพ Heatmap จึงไม่เปลี่ยนผลคำนวณอุณหภูมิโดยตัวมันเอง

สมการที่ใช้คือ `T(x,y) = Σ(T_i / d_i^p) / Σ(1 / d_i^p)` โดย `d_i` เป็นระยะ Euclidean ในหน่วยพื้นที่จริง และ `p` คือ Power ที่ตำแหน่งวัดให้ค่าตรงกับอุณหภูมิที่กรอกโดยตรง ไม่มีการหารด้วยศูนย์ ผลประมาณอยู่ระหว่างค่าต่ำสุดและสูงสุดของจุดวัด ไม่สุ่มสี และไม่ปรับค่าอุณหภูมิจริงเพื่อให้ตรงช่วงสี อ้างอิงแนวทาง [Inverse Distance Weighting ของ Esri](https://pro.arcgis.com/en/pro-app/3.5/help/analysis/geostatistical-analyst/how-inverse-distance-weighted-interpolation-works.htm)

สีเป็นค่าประมาณเชิงพื้นที่ ไม่ใช่ค่าที่วัดเพิ่ม และไม่ใช่การแก้สมการถ่ายเทความร้อนหรือทำนายค่าที่ได้รับการยืนยัน จุดสีขาวและป้ายแสดงค่าที่วัดจริง ส่วนสถิติด้านล่างคำนวณจาก 6 จุดวัดเท่านั้น ใน PNG มีคำอธิบายว่าเป็น Estimated field

เลือก **Measured region · Linear** เพื่อใช้พฤติกรรมเดิม: bilinear สำหรับจุดแบบสี่เหลี่ยม 2×3 หรือ triangular linear สำหรับพิกัดทั่วไป และเว้นว่างนอกบริเวณที่จุดวัดครอบคลุม โหมดนี้ห้ามจุดทั้งหมดอยู่ในเส้นตรงเดียวกัน ส่วน IDW รองรับกรณีวางจุดเป็นเส้นได้ ทั้งสองโหมดห้ามจุดซ้อนกันหรืออยู่นอกพื้นที่

เลือก **Measured region · Smooth** หากต้องการสีเปลี่ยนต่อเนื่องนุ่มนวลกว่า Linear ใช้ cubic interpolation ที่คงค่าผ่านจุดวัดและมีความชันต่อเนื่องระหว่างสามเหลี่ยม ตาม [Matplotlib CubicTriInterpolator](https://matplotlib.org/stable/api/tri_api.html#matplotlib.tri.CubicTriInterpolator) ค่าประมาณอาจเกินต่ำสุด/สูงสุดของจุดวัดได้ สีถูกจำกัดตาม Scale minimum/maximum ที่เลือก ขอบนอกยังคงเป็นบริเวณที่จุดวัดครอบคลุมและอาจเป็นรูปหลายเหลี่ยมตามตำแหน่งจริง ไม่เติมข้อมูลนอกขอบ ถ้าต้องการสีเต็มสี่เหลี่ยมให้ใช้ Full area · IDW ทั้ง preview และ PNG ใช้การแสดงผลสีแบบ bilinear เพื่อลดขอบพิกเซล โดยไม่เปลี่ยนค่าจุดวัดหรือคำนวณ Smooth แทน Linear โดยอัตโนมัติ

ไฟล์ตั้งค่าเดิมที่ไม่มี `estimation_method`/`idw_power` จะได้ค่าเริ่มต้น `idw`/`2.0` โดยคงชื่อ พิกัด และอุณหภูมิเดิมไว้ การเปลี่ยนขนาดพื้นที่ไม่ขยับพิกัดเดิมอัตโนมัติ หากพิกัดอยู่นอกขนาดใหม่ต้องแก้ก่อนอัปเดต

## Compress PDF

เลือกเมนู **Compress PDF** แล้วกด **Add PDFs** หรือลาก PDF หลายไฟล์เข้าหน้าจอ เลือกโฟลเดอร์ปลายทางด้วย **Change** แล้วกด **Compress PDFs**:

- **Lossless**: จัดโครงสร้าง PDF และบีบอัดข้อมูลโดยไม่ลดคุณภาพภาพเดิม
- **Balanced** (เริ่มต้น): บีบอัดภาพเป็น JPEG quality 80 และลดภาพที่เกิน 180 DPI ลงเป็น 150 DPI
- **Smallest**: บีบอัดภาพเป็น JPEG quality 60 และลดภาพที่เกิน 120 DPI ลงเป็น 96 DPI เหมาะกับการดูบนหน้าจอ ภาพอาจเสียรายละเอียด

ใช้ [PyMuPDF Document.rewrite_images และ Document.save](https://pymupdf.readthedocs.io/en/latest/document.html) ประมวลผลภายในเครื่อง โดยไม่แปลงหน้าทั้งหน้าเป็นรูป ข้อความที่เดิมเลือกและค้นหาได้ยังคงอยู่ การบีบอัดไม่เพิ่ม OCR ให้ไฟล์สแกน รองรับ PyMuPDF 1.28.2 ขึ้นไป

ผลลัพธ์อยู่ในโฟลเดอร์ `<original>_compressed`, `<original>_compressed_2`, … ภายใต้ปลายทาง ชื่อ `<original>_compressed.pdf` ไม่เขียนทับต้นฉบับหรือผลลัพธ์ครั้งก่อน รายการแสดงขนาดก่อน/หลังและเปอร์เซ็นต์ที่ลดได้ พร้อมยอดรวมด้านล่างและปุ่ม **Open folder** หากบีบอัดแล้วไฟล์ไม่เล็กลง จะเก็บสำเนาต้นฉบับแทนและแสดง **No further reduction** จึงไม่มีการรับประกันเปอร์เซ็นต์ลดขนาด

งานหนักทำใน process แยกที่มี priority ต่ำกว่าปกติ **Cancel** สีแดงขอยกเลิกและรอ operation ของ PDF ปัจจุบันถึงจุดหยุดที่ปลอดภัย ไฟล์ที่บันทึกสมบูรณ์แล้วคงอยู่ ส่วนไฟล์ที่ยังไม่ publish จะไม่ถูกส่งออก หากไฟล์หนึ่งผิดพลาดจะรายงานในรายการและทำไฟล์ถัดไปต่อ คิวอยู่ระหว่างสลับเมนู รองรับ PDF ที่ไม่ต้องใช้รหัสผ่าน และไม่รับไฟล์ที่มี signature fields เพื่อหลีกเลี่ยงการทำให้ลายเซ็นใช้ไม่ได้

ตรวจด้วย `tests/test_compress.py` ครอบคลุมทุก preset, ข้อความ/ลิงก์/ฟอร์ม/annotation, จำนวนหน้า/การหมุน, ต้นฉบับไม่เปลี่ยน, ชื่อผลลัพธ์ไม่ชน, ไฟล์ล็อก, ยกเลิก และทำ batch ต่อหลังไฟล์ผิดพลาด ส่วน `tools/smoke_compressor.py` ตรวจเมนูและ bridge จริง การ route ลากวาง คิวไม่หาย การยกเลิก และหน้าต่าง 1280×820 / 1080×700

## Searchable PDF · OCR

เปิดเมนู **Searchable PDF** แล้วเพิ่มหรือลาก PDF สแกนเข้ามา เลือก **Choose languages** เพื่อเลือกภาษาที่อยู่ในเอกสารจริงได้ 1–5 ภาษา ไทยและอังกฤษพร้อมใช้งานในโปรเจกต์ มีรายการโมเดลภาษา/รูปแบบอักษร 123 ชุดจาก [Tesseract tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast) เช่น จีน ญี่ปุ่น เกาหลี ฝรั่งเศส เยอรมัน อาหรับ ฮินดี ลาว เขมร พม่า และเวียดนาม ไม่ใช่การตรวจจับภาษาอัตโนมัติ

ภาษาที่ยังไม่มีจะแสดง **Download** พร้อมขนาดไฟล์ กด **Download languages** เพื่อดาวน์โหลดเฉพาะแพ็กที่เลือกจาก upstream โดยตรง ใช้อินเทอร์เน็ตเฉพาะการดาวน์โหลดแพ็ก ไม่ส่งเอกสารออกจากเครื่อง หลังดาวน์โหลดแล้วใช้ OCR ออฟไลน์ได้ มีการตรวจขนาดและ Git blob checksum ตาม revision ที่ตรึงไว้ก่อนใช้งาน แพ็กที่ขาด/เสียหายจะไม่ถูกส่งให้เอนจิน

เลือกโปรไฟล์ **Light · 150 DPI** สำหรับเครื่องที่ทรัพยากรน้อย, **Balanced · 200 DPI** เป็นค่าเริ่มต้น หรือ **Detailed · 300 DPI** สำหรับตัวอักษรเล็ก ทำงานทีละหน้าใน process แยกที่ priority ต่ำกว่าปกติ และใช้ OCR thread เดียว จำกัดภาพสำหรับวิเคราะห์ประมาณ 12 ล้านพิกเซลและด้านยาว 10,000 พิกเซลต่อหน้า ขนาดเกินจะลดความละเอียดสำหรับ OCR โดยภาพต้นฉบับยังคงอยู่ จึงไม่ต้องมี GPU, CUDA, PyTorch หรือโปรแกรม Tesseract/Ghostscript แยกจาก PyMuPDF wheel ที่ใช้ในโปรเจกต์ อ้างอิง [PyMuPDF OCR support](https://pymupdf.readthedocs.io/en/latest/installation.html#enabling-integrated-ocr-support) และ [Tesseract thread settings](https://tesseract-ocr.github.io/tessdoc/FAQ)

กด **Create searchable PDFs** เพื่อเพิ่มชั้นข้อความที่มองไม่เห็นบนภาพ/เนื้อหาต้นฉบับ โดยไม่เอาภาพที่เรนเดอร์ไปแทนหน้าเดิม คงการหมุน crop box ลิงก์ และเนื้อหาเดิม หน้าใดมีข้อความที่ดึงอ่านได้อยู่แล้วจะถูกข้ามทั้งหน้าเพื่อไม่สร้างข้อความซ้ำ รวมถึงกรณีมีเพียงเลขหน้าหรือหัวกระดาษเป็นข้อความ จึงยังไม่ใช่ OCR เฉพาะส่วนภาพบนหน้าที่มีข้อความปนอยู่

ผลลัพธ์เป็น `<original>_searchable.pdf` ในโฟลเดอร์ `<original>_searchable`, `<original>_searchable_2`, … ไม่ทับต้นฉบับ คิวและตัวเลือกอยู่ระหว่างสลับเมนู โฟลเดอร์ ภาษา และโปรไฟล์จำไว้เมื่อเลือกโฟลเดอร์/เริ่มงาน หากผิดพลาดหนึ่งไฟล์จะทำไฟล์ถัดไปต่อ แสดงจำนวนหน้าที่มีข้อความหลังประมวลผล รวมหน้าที่มีข้อความเดิม **Cancel** สีแดงรอจบ operation ของหน้าปัจจุบันแล้วทิ้ง PDF ที่ยังทำไม่ครบ ไฟล์ก่อนหน้าที่บันทึกสำเร็จยังอยู่

เมื่อ OCR จบจะแสดง popup สรุปจำนวนไฟล์ที่บันทึก/ผิดพลาดและพาธผลลัพธ์ พร้อม **Done** และ **Open output folder** โดยปุ่มเปิดโฟลเดอร์แสดงเมื่อมีไฟล์บันทึกสำเร็จ แยกข้อความกรณียกเลิก ผิดพลาดบางไฟล์/ทั้งหมด หรือไม่พบข้อความ กด Done/Escape แล้วไม่เด้งซ้ำจาก polling และไม่แสดง popup สร้าง PDF เมื่อดาวน์โหลดภาษาเสร็จ

เหมาะกับเอกสารพิมพ์ที่สแกนชัด ความแม่นยำขึ้นกับภาษา ฟอนต์ ทิศทาง และคุณภาพภาพ ควรตรวจชื่อและตัวเลขสำคัญ ไม่รับ PDF ที่ต้องใช้รหัสผ่านหรือมี signature fields ทดสอบ OCR จริงไทย–อังกฤษ การดาวน์โหลดภาษาฝรั่งเศส และ Windows x64 ที่หน้าต่าง 1280×820 / 1080×700 แล้ว แต่ยังไม่รับรอง laptop ทุกสเปก/ระบบปฏิบัติการ หรือความแม่นยำของทุกภาษา

ไฟล์โมเดลอยู่ใน `ocr_data/tessdata/` ไทย/อังกฤษเป็นส่วนหนึ่งของซอร์ส ภาษาเพิ่มเติมที่ดาวน์โหลดถูก ignore จาก Git เมื่อต้องย้ายเครื่องแบบออฟไลน์ให้คัดลอกโฟลเดอร์นี้พร้อมแอป ดูแหล่งที่มาและสัญญาอนุญาตใน `ocr_data/README.md`

### ผลทดสอบฟอนต์ ขนาด และประสิทธิภาพ OCR

สร้างชุดทดสอบสังเคราะห์ 6 ฟอนต์/ภาษา ได้แก่ อังกฤษ Tahoma, Arial, Times New Roman และไทย Tahoma, Angsana New, Cordia New ขนาด 6/8/9/10/12/14/16 pt รวมต้นฉบับ 84 แถวในสภาพภาพชัด 300 DPI และภาพลดคุณภาพ ทดสอบ 3 โปรไฟล์เป็น 252 ผลวัด โดยแยกข้อความคาดหวังและพิกัดแถวไว้ต่างหาก การจัดรูปภาษาไทยใช้ MuPDF Story เพื่อคงสระ/วรรณยุกต์

คืน decoded-image cache หลังจบแต่ละหน้าเพื่อลด RAM ใน process OCR ผลวันที่ 2026-11-08 บนเครื่องพัฒนา: ภาพชัด 6 หน้า Balanced peak working set ลดประมาณ 258.8 → 132.8 MB และ Detailed 302.6 → 176.6 MB เวลาใกล้เดิม ข้อความก่อน/หลังตรงกันทุกแถวและภาพทุกหน้าตรงต้นฉบับ ไม่ใช่ตัวเลข RAM รวมของทั้งแอปหรือการรับรองทุกเครื่อง

ภาพชัดในชุดนี้ Detailed ได้ CER 4.95% เทียบ Balanced 7.40% แต่ภาพต้นฉบับคุณภาพต่ำ Balanced ได้ CER 7.18% เทียบ Detailed 7.88% ฟอนต์และคุณภาพภาพมีผล จึงยังไม่มีขนาดเล็กสุดที่รับรองได้ทุกฟอนต์และไม่ควรสรุปว่ายิ่ง DPI สูงยิ่งแม่นเสมอ CER ใช้ Levenshtein หลัง Unicode NFKC และตัด whitespace โดยยังนับตัวเลข/เครื่องหมาย/ตัวพิมพ์ผิด

```powershell
.\.venv\Scripts\python.exe tools\report_ocr_quality.py output\pdf\ocr-test-kit-new
```

ตัว benchmark ทำ OCR จริงทีละ process วัดเวลาของเอนจินและ peak working set ก่อนเรนเดอร์ตรวจผล `retain-cache` จำลองพฤติกรรมก่อนแก้โดยปิดเฉพาะการคืนแคช ไม่ mock ข้อความ ผลเปรียบเทียบวัดอย่างละหนึ่งรอบจึงไม่ใช้ส่วนต่างเวลาเล็กน้อยอ้างว่าเร็วขึ้น ต้องมี Windows fonts ตามรายการจึงสร้างชุดฟอนต์นี้ได้ ส่วนผลทดสอบไม่ครอบคลุมทุกภาษา ลายมือ หรือ layout เอกสารจริง

## การเก็บข้อมูล

- การตั้งค่า PDF: `ui_settings.json`
- การตั้งค่า Heatmap: `heatmap_settings.json`
- ขนาด ตำแหน่ง และสถานะหน้าต่างหลัก: `workspace_settings.json`
- โฟลเดอร์ล่าสุดของเมนูจัดการหน้า PDF: `organizer_settings.json`
- โฟลเดอร์ล่าสุดของ Compress PDF: `compressor_settings.json`
- โฟลเดอร์ล่าสุด ภาษาและโปรไฟล์ OCR: `ocr_settings.json`
- ค่าเริ่มต้น Heatmap: `config.json`
- ผลลัพธ์เริ่มต้น: `output/` หรือโฟลเดอร์ที่เลือกในแต่ละเครื่องมือ

เริ่มด้วยการตั้งค่าเริ่มต้น เพื่อไม่ให้เขียนผลลัพธ์ลงโฟลเดอร์ต้นฉบับโดยไม่ตั้งใจ
Heatmap จะเติมเลขท้ายชื่อเมื่อไฟล์ส่งออกมีอยู่แล้ว
ระหว่างแปลง PDF หรือสร้าง Heatmap โปรแกรมจะรอให้งานเสร็จก่อนยอมปิดหน้าต่าง

## โครงสร้างและการทดสอบ

`main_app.py` เป็นตัวรวมหน้าต่างและส่งคำสั่งไปยัง `DocumentAPI`, `OrganizerAPI` และ `HeatmapAPI`
`ui/management.html` เป็นเมนูหลัก หน้าของแต่ละเครื่องมือแยกบริบท HTML/CSS/JS และใช้ Python bridge ร่วมกัน
`heatmap/` เป็นแกนคำนวณเดิม และ `pdf_to_jpg.py` เป็นแกนแปลง PDF เดิม
`organizer_app.py` ควบคุมงานจัดการหน้า PDF, `organize_pdf.py` คัดลอกหน้าตามตัวเลือก, `organizer_ui/` เป็นหน้าจอ และ `pdf_worker.py` แยกทั้งงานแปลงภาพและจัดการ PDF ไป process เบื้องหลัง
เวอร์ชันโปรแกรมระบุในไฟล์ `VERSION`

เครื่องมือตามคำสั่งยังใช้ได้ผ่าน `pdf_to_jpg.py` และ `heatmap_cli.py --config config.json`

Smoke test เปิดหน้าต่างชั่วคราว ตรวจทั้งสองเครื่องมือ การสลับหน้า และการส่งออกจริง แล้วปิดเอง

`smoke_organizer.py` ตรวจ grid/list ภาพย่อ การลาก PDF เลือกหลายหน้าด้วย Shift ลากเรียงข้ามไฟล์ ลบ/ย้อนกลับ เมนูหมุน/พลิก popup พร้อม Zoom/Fit และ native Ctrl+wheel ที่ไม่เปลี่ยน WebView zoom ส่งออกเฉพาะหน้าที่เลือก เนื้อหาและมุมหมุนในผลลัพธ์ทั้งสามโหมด การยกเลิก การโหลดภาพตามตำแหน่งเลื่อน และ layout ที่ 1280×820 กับ 1080×700 ภาพหน้าจอเก็บใน `.runtime-tmp/` มี unit test เปรียบเทียบภาพก่อน/หลังพลิกและการหมุนร่วมกับ crop เดิม

`smoke_pdf_workflow.py` ตรวจการลากไฟล์ผ่าน native WebView2 bridge ทั้งหน้าหลักและ iframe การเลือกหน้าไม่ถูกต้อง การส่งออกทุกตัวเลือกใน dropdown การกดยกเลิกและเก็บภาพที่เสร็จแล้ว รวมถึง layout ที่ 1280×820 และ 1080×700 ภาพหน้าจอทดสอบเก็บใน `.runtime-tmp/` ซึ่งไม่รวมใน Git

วัดการตอบสนองก่อน/หลังแยก process ด้วย `.\.venv\Scripts\python.exe tools\benchmark_pdf_responsiveness.py` ใช้ PDF ทดสอบ vector หนาแน่น 3 หน้า ที่ 300 DPI ผลบนเครื่องพัฒนาพบช่วงสะดุดสูงสุดของ Python heartbeat ลดจาก 783.7 ms เหลือ 23.9 ms เวลาแปลง 3.25 และ 3.45 วินาทีตามลำดับ ตัวเลขนี้วัดความต่อเนื่องของส่วนควบคุมด้วยไฟล์สังเคราะห์ ผลกับไฟล์จริงและเครื่องอื่นอาจต่างกัน
